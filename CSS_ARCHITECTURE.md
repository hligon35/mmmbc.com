# CSS & Static Asset Architecture

The site has two consolidated stylesheet entry points:

| Bundle | Scope | Contents |
|---|---|---|
| `static-style.css` | Public website | Site foundation, navigation, components, schedule, responsive rules, home refinements, scanner, and giving-page styles. |
| `admin/public/admin-style.css` | Admin website | Admin foundation, dashboard, directory, structural overrides, canonical header/navigation, and finance tools. |

`theme.css` remains a separate generated theme layer because the admin Site
Editor writes it dynamically. It is imported by `static-style.css` and should
not contain layout or component rules.

## Loading rules

- Every public root page loads `/static-style.css` once.
- Pages under `Pages/` load `../static-style.css` once.
- Scanner and giving-page rules are included in the public bundle; they are
  scoped by their existing page classes and do not need separate links.
- Every admin page loads `/admin/admin-style.css` once.
- `admin-structure-overrides.js` may still be injected by the local server or
  Worker because it provides behavior, not CSS.
- Public and admin bundles are never loaded together.

## Source and deployment mirror

The source files are `static-style.css` and `admin/public/admin-style.css`.
`cf_site/` is generated by:

```powershell
npm run build:cf
```

The build copies both bundles into the deployable mirror and removes stale
stylesheet assets so old cascade layers cannot survive a deployment.

When adding styles, place public rules in `static-style.css` and admin rules
in `admin/public/admin-style.css`. Use a page class or component namespace for
page-specific rules so bundling cannot create cross-page interference.
