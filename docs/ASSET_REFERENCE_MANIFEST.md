# Asset Reference Manifest

Date: 2026-08-04
Purpose: distinguish source-of-truth assets from generated deploy artifacts.

## Source of Truth (Do Edit)

Public-site source files:

- Root HTML, CSS, JS, and JSON data files (for example index.html, script.js, public-base.css, announcements.json).
- Pages directory under Pages/.
- Media directories under Icons/, ConImg/, rental/, bulletins/.

Admin-site source files:

- admin/public/* (JS, CSS, HTML) except generated outputs elsewhere.

Worker and server source files:

- src/*.js
- admin/server.js and supporting admin modules.

Build and deployment sources:

- scripts/build_cf_site.mjs
- wrangler.jsonc

Migrations and persistent data assets:

- migrations/*.sql
- JSON data that is operationally consumed by runtime.

## Generated Output (Do Not Treat as Canonical Source)

- cf_site/**

Generated by:

- npm run build:cf
- script: scripts/build_cf_site.mjs

Behavior:

- Build script recreates cf_site from source files and injects admin structure tags.
- Cloudflare Worker assets deployment uses cf_site as upload directory.

## Build Mapping (High-Level)

Inputs mirrored into cf_site:

- Root selected public files.
- Pages, Icons, ConImg, rental, bulletins directories.
- admin/public mirrored to cf_site/admin with exclusions and injection normalization.

Exclusions in admin mirror:

- login.html
- login.js
- server.js
- admin/public/data/

## Verification Rules During Cleanup

- Never hand-edit cf_site files as source changes.
- Edit source files only, then run npm run build:cf.
- Re-check that cf_site reflects intended source updates.
- Preserve existing deployment workflow that depends on cf_site assets.
